# doubt-ledger

**Trust relocates blindness; it does not delete it.** This ledger is where the
relocation gets written down — an append-only, git-backed record of what you
stopped checking, why, what covers it, and what event brings it back for a look.

Origin (real, 2026-10-02): a 21-hour live run of sub-agent lanes whose every
output passed independent verification — and whose checkers (the verifying
pulse, the reading human) stopped being audited somewhere along the way.
The doubt was relocated, not deleted. This repo is the surface that makes the
relocation legible.

## Entry grammar (all five required — no field may be empty)

```json
{
  "id": "a1b2c3d4e5f6",
  "ts": 1762051200,
  "stopped_checking": "pr-93 review",
  "because": "builder sealed 4 pins independently verified",
  "covered_by": "builder RESULT.md + pins/failfirst.log",
  "revisit_trigger": "casey-merged-pr-93",
  "kind": "event",
  "status": "open"
}
```

`kind: condition` entries carry `expr` instead of a single trigger.
Discharge requires a written reason — an unreasoned discharge is just
blindness again.

## What it proves (pins P1–P5)

| pin | claim |
|-----|-------|
| P1 | grammar-enforced — an incomplete entry is rejected and names the missing field |
| P2 | append-only — any rewritten stored line is refused on load (per-line checksum) |
| P3 | fire-and-due — a trigger fires exactly its entries, marks them `due`, discharge demands a reason |
| P4 | git-resume — checkpoints commit the ledger; a fresh process over the same dir resumes byte-identical |
| P5 | coverage-query — "what is trust letting through HERE" is always answerable by substring |
| P6 | selective-disclosure export — a filtered slice writes itself as a standalone file with recomputed per-entry checksums, bound to the live tip root |
| P7 | root-signing — the fnv1a-64 tip root (chain over per-line checksums, genesis-anchored) is Ed25519-signable; one signature covers every entry by induction |
| Q1–Q4 | qmr1-compatible export — a filtered slice also writes itself as a `qmr1` receipt chain (`quilt-mcp-receipts` dialect, spike v1): `id = SHA-256("qmr1:"+seq+":"+prev+":"+canonicalJSON(body))`, `sig = HMAC-SHA256(secret, "qmr1:sig:"+id)`, re-serialization and key-reorder safe, tamper and wrong-secret refused by line |
| Q2A1–Q2A4 | optional qmr2-§8 attribution export — `signer=<Ed25519 PEM>` adds `sigAlg:"ed25519"`, `sigKeyFp = sha256(SPKI PEM)`, and an Ed25519 sig over `"qmr1:sig:"+id`; verified by the real `quilt-mcp-receipts` v3 keyring verifier; `signer=None` qmr1 rows stay byte-unchanged; empty dev secret is refused |

Run: `python3 tests/pins_ledger.py`, `python3 tests/pins_export.py`,
`python3 tests/pins_qmr1.py`, and (with a `quilt-mcp-receipts` checkout)
`QMR_RECEIPTS_DIR=../quilt-mcp-receipts python3 tests/pins_qmr2_attribution.py`
(core stdlib only; signing/attribution needs `cryptography`. FAIL-first logs in
`pins/failfirst.log`, `pins/failfirst-wave2.log`, `pins/failfirst-wave3.log`).

## qmr1 naming alignment (wave-3, consume-don't-rival)

`export_qmr1()` emits the same selective slice in the dialect Casey minted
for `SuperInstance/quilt-mcp-receipts` (spike v1): five fields per line
(`seq/prev/body/id/sig`), SHA-256 chain over canonical JSON, HMAC-SHA256
signatures. Design intent: one fleet receipt dialect, not three — and the
same cheap hedge direction as IETF
draft-sharif-agent-audit-trail-05 (JCS-canonical hash chains for agent audit
trails). Any qmr1 reader — including that MCP organ — can consume a
doubt-ledger export without knowing this repo exists.

Interop evidence (this branch): a 3-receipt export generated by
`export_qmr1()` verifies clean under the qmr1 reference implementation's own
`canonicalJSON`/`receiptId`/`receiptSig` (JS, `quilt-mcp-receipts`
`server.mjs` lineage), and `verify_qmr1()` re-derives every id/sig
independently in stdlib Python (Q1–Q4).

Wave-4 qmr2 attribution (additive): `export_qmr1(..., signer=<Ed25519 PEM>)`
opts a row into the qmr2-§8 attribution dialect — `sigAlg`, `sigKeyFp`, and an
Ed25519 signature over the same `"qmr1:sig:"+id` preimage. The signer
fingerprint is sha256 over the normalized SPKI PEM, byte-identical to
`quilt-jev-toolkit` / `quilt-mcp-receipts` v3. The attribution body carries
qmr1's required non-empty `kind`/`ts` envelope around the original entry
record; default `signer=None` exports remain the wave-3 five-field HMAC rows.
Q2A1–Q2A4 pins run against the real `verify_chain` / `verify_attribution`
over MCP stdio, including fail-closed `E_UNKNOWN_SIGNER` and tamper refusal.

Secret resolution: explicit argument > `DOUBT_QMR1_SECRET` >
`MCP_RECEIPT_SECRET` (the variable the qmr1 organ itself reads) > empty key.
The empty-key fallback keeps exports runnable in dev; it is a documented dev
mode, never presented as a seal.

## Honest limits

1. The ledger records doubt, it doesn't rank it — a cheap doubt and an
   existential one take the same five fields. Severity is unbuilt.
2. The checksum is fnv1a-64 (integrity mark, not a signature) — mitigated,
   not solved, by P7's optional Ed25519 root signature: one honest key holder
   still stands between the ledger and a forged tip.
3. Condition expressions are exact-string matches, not a real expression
   language.
4. Nobody audits the ledger-keeper. A doubt-ledger that lies about its own
   entries is just a diary. (Pins prove the store refuses tampering *on load*
   — but the keeper chooses when to load.)
5. An export proves its included entries are byte-intact; it does not prove
   the filter was complete. Selective disclosure hides by construction —
   completeness is the verifier's question, never the exporter's claim.
6. qmr1 interop is canonical-form interop, not byte-level: ASCII string/int
   bodies are exactly dialect-compatible with the JS reference, but non-ASCII
   text and floats are a divergence class (escape policy / float repr).
   Keep qmr1 bodies in plain ASCII strings and ints.
7. qmr1's spike signature is HMAC with a shared secret — verification proves
   possession of the secret, not identity. The Ed25519 root signature (P7)
   remains the identity story; qmr1 is the transport dialect.
